1 Run behaviour background window, session backups▶
Background mode runs AI tabs in a separate window that never steals focus. Leave that window open and don't minimize it.
Running with Chrome minimized? Chrome stops laying out and stops the timers of a window that is minimized or completely covered — that is a browser rule, not a setting, and it is why Gemini stalls or fails. The extension now works around it (it keeps the page's frame, resize and visibility callbacks turning over from the background, and restores a window it finds minimized). For a permanent fix on a portable Chrome, add these switches to the shortcut or .bat you launch it with:
--disable-backgrounding-occluded-windows --disable-background-timer-throttling --disable-renderer-backgroundingWith those, a minimized Chrome runs exactly as fast as a visible one, and the window is never pulled back to the front.

🚀 Fast Submit + Timed Recovery send all prompts now, collect & update later▶
Phase 1 — 🚀 Fast Submit: for every post above, the extension opens the AI, pastes the prompt + article, presses send, verifies and saves the real conversation link, and closes the tab immediately — no waiting for the AI to write (it keeps writing on the AI's servers). Phase 2 — ⏰ Recovery: at the time you set (or when you press the button), each saved chat is reopened one by one, the finished HTML is collected, and the related post is updated. Web AI providers only. ChatGPT: Temporary Chat/history-off must be disabled so a durable /c/… link can be created. Gemini works differently: it discards a chat whose first reply is cut off, so Gemini tabs are NOT closed right after sending — up to 3 tabs stay open in a pipeline while the next posts are submitted, and each tab closes only after its reply finishes and its link survives a reload check. "Gemini Apps Activity" must be ON and the right Google account logged in; if a finished chat still vanishes, the batch pauses immediately with instructions. Before every Gemini send the model is strictly locked to Flash + Extended thinking — if that cannot be verified, that post fails and the batch keeps going. Keep Chrome open — you can minimize it: every AI tab is kept awake so Chrome's background throttling cannot stall or slow the replies.
On: submit ALL posts at once — no auto timer and no per-cycle system. Then press “⏰ Recover & Update Now” yourself whenever you like. Off: use the Recovery delay and Posts-per-cycle settings below.

6 Retry & recovery failed posts, audit issues, fallback AI▶
Failed posts — when a post fails to generate or save, Step 1 reopens the saved AI session and re-reads the code it already produced; Step 2 retries in a brand-new AI session.
Audit issues — posts that saved but whose audit found problems (red rows). Step 1 re-reads the saved session's code box; Step 2 re-runs the AI to rewrite the post. Solved posts drop out of the Audit Issues box.
If the main AI truncates, returns no code block, or fails a post, that post is retried once with this AI.
